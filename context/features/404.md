# 404 Page

On-brand error page. Not a dead end — helps the user get back on track.

## Prerequisites

Build `home-phase-1-shell.md` first. Reuses standard layout.

## Scope

- `app/not-found.tsx` — catches 404s across the site
- Page content:
  - Large micro-label (`L O S T`)
  - Display h1 — plain and slightly warm ("Looks like we took a wrong turn." or similar; Chris to pick)
  - Short supporting paragraph (one sentence)
  - "Start here" nav block — 3-4 links to the most useful destinations: Home, Services, Work, Contact
  - Optional: small WhatsApp link ("or tell us what you were looking for")
- Uses the same nav + footer as the rest of the site
- `generateMetadata` with `noindex` (404s shouldn't be indexed)

## Acceptance criteria

- [ ] Hitting any non-existent URL shows the custom 404
- [ ] Page matches site design (micro-label, display type, layout)
- [ ] All links work and navigate as expected
- [ ] Metadata includes `robots: { index: false }` — 404 pages shouldn't be indexed
- [ ] Mobile and both themes hold
- [ ] Page feels friendly, not cold
- [ ] No banned words

## Implementation notes

- `app/not-found.tsx` is Next.js's built-in 404 — no custom routing needed
- Uses the `(marketing)` layout implicitly if placed correctly, or copy the nav/footer import into `app/not-found.tsx` directly
- Keep copy short — 1 h1 + 1 sentence + a nav block is plenty
- Don't make the page cute or funny — warm and useful beats clever

## Out of scope for this phase

- Search bar on 404 — not needed for a small site
- Suggested pages based on the bad URL — not worth the engineering
- Fun illustrations — not in brand

## Done when

Any bad URL shows the custom 404, design matches site, links work, metadata includes noindex, mobile and both themes render.
